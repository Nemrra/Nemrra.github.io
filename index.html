Broadband Amplitude-shift Keying Transceiver

A broadband ASK modulation-demodulation transceiver taking analog design from theory to a debugged hardware prototype. The chain integrates a BJT series-switch mixer, a high-Q multiple-feedback bandpass filter, a Gilbert-cell four-quadrant multiplier, and a Schmitt-trigger decision device, each characterised in the frequency domain and validated from SPICE to hardware, emphasising working with device non-idealities rather than suppressing them.

Tech stack: Matlab and Simulink (Signal Processing, System ID Toolboxes), Python (SciPy), SPICE (KiCad, LTspice)
Analogue Design Skills
  • Complete frequency-domain characterisation of circuit modules (TF derivation, pole-zero shaping, high-Q active filter design).
  • Simulation-to-hardware validation, LTI system identification, non-ideal properties.
  • Modularity and cascade parasitics, and use of high-drive buffers.
  • IC selection and characterisation through documentation, accounting for non-ideal op-amp parameters: slew rate, finite open-loop gain, gain-bandwidth product, saturation-rail headroom, input offset, and CMRR, and approximating for such in the LTI transfer function model.
  • Biasing for operating point, transconductance, and headroom-vs-linearity trade-offs; feedback design (negative for linearity, positive for regenerative hysteresis).
  • Exploiting device non-idealities (parasitics, fT roll-off) rather than suppressing them.
ASK Modulation-Demodulation System
Modulating Mixer

BJT series-switch topology gating the carrier under binary control, tuned for hard saturation-to-cutoff switching (base overdrive for clean gating, full carrier suppression in the off-state) and near-unity modulation index across a wide carrier range.

Active High-Q (Multiple Feedback) Bandpass Filter

High-order frequency-domain transfer function derivation, designed for specified passband gain, centre-frequency and attenuation slope. Hardware-verified and debugged through LTI system identification. Intentionally tuned for Q-vs-bandwidth tradeoff.

Gilbert Cell: Four-Quadrant Multiplier

Tuned through emitter degeneration for input linearity and dynamic range, tail-current biasing to set transconductance and the operating point, and differential-pair matching for offset nulling and carrier feedthrough suppression. Balanced for port-to-port isolation (RF-LO-IF) with common-mode rejection, translinear-loop symmetry for four-quadrant operation, and headroom-vs-linearity trade-off across the stacked topology.

Characterised the cell’s inherent single-pole low-pass roll-off, arising from transistor parasitic capacitances, Miller effect at the RF/IF nodes, and finite device fT rather than an added filter, and exploited it to attenuate the sum-frequency mixing product and residual carrier, smoothing the recovered baseband envelope ahead of the downstream Schmitt trigger’s hysteresis decision.

Schmitt Trigger Decision Device

Op-amp topology using positive feedback for regenerative switching between saturation rails, with a tuned hysteresis window for noise immunity against envelope logic-high ripple, and a supply-derived reference divider so the switching thresholds track positive supply drift for reliable single-supply operation.

Formally-Verified Multi-Mode Digital Timepiece: Feature-Layered SystemVerilog RTL on Cyclone V FPGA

A multi-mode digital timepiece (settable clock, lap-capable stopwatch, editable countdown timer, and PWM brightness control) implemented as fully synchronous RTL and taken through a complete industry-representative flow: lint-clean SystemVerilog, cocotb/pytest regression, k-induction formal proof of every sequential submodule, Quartus synthesis and place-and-route, and gate-level netlist inspection. Built by feature layering (Watch V1→V4) from small, parametrised, single-responsibility modules, with correctness treated as a first-class deliverable rather than an afterthought.

SystemVerilog · Quartus Prime (Cyclone V, DE1-SoC) · Yosys / SymbiYosys / Z3 (formal, SMT-LIB) · Icarus Verilog · Verilator · cocotb + pytest · Verible · Docker dev containers · git · VaporView
Architecture & RTL Design
  • Decomposed the system into ~20 reusable parametrised modules (up/down counters, modulo-N and cascaded HMS counters (17 FFs of timekeeping state), restartable rate generators, binary-to-BCD converters with explicit width casting, PWM generators, rising-edge detectors, button hold/auto-repeat logic, arming latches, and edit-mode selectors) composed via packed structs to route wide buses through multiplexers as single logic vectors.
  • Separated data path from control throughout: the stopwatch routes counter output through a snapshot multiplexer to the display driver, while an independent FSM drives reset/enable/freeze, so lap capture required zero modification to the counter itself, validating the decomposition.
  • Modelled the stopwatch as two orthogonal state machines (running/stopped × live/frozen), with control-FSM state output-encoded directly as its control signals rather than held in a separate state register, eliminating the output-decode layer entirely.
  • Encoded the timer FSM as {running, one-hot mode_enable[2:0]} (4 bits), letting each one-hot bit drive one counter’s edit_mode directly with no decoder; resolved the documented edit-vs-run race (edit_mode_selector has no reset pin) by permitting both modes for exactly one clock cycle, with edit taking priority and cancelling the run transition: a resolution the formal proof accepts.
  • Derived the editable countdown’s borrow-out semantics from the 74LS193 datasheet: BO̅ = NAND(Q̅₀..Q̅₃, C̅P̅D̅), whose rising edge clocks the next cascaded stage exactly once per underflow, and mapped it to a synchronous equivalent gated by tick, edit_mode, and clr.
Timing, Synchronisation & CDC Hygiene
  • Satisfied the first-tick timing constraint (first centisecond increment exactly 10 ms after start, never sooner) by gating the rate generator with .run(enable && !rst) rather than enable alone. Otherwise the free-running generator desynchronises from the reset counter chain and the first tick arrives early.
  • Synchronised asynchronous active-low key inputs through a two-flip-flop cascade, trading two cycles of latency for an exponential reduction in metastability propagation probability into downstream FSMs.
  • Applied Gray-coded switch decoding to the brightness control so adjacent levels differ by a single bit, and set a 1 ms PWM period (12.5-100% duty), above the flicker-fusion threshold, for visually steady dimming; deployed it as a non-invasive wrapper module intercepting the blanking path between timepiece and board top without modifying either.
Formal Verification (Yosys → SMT-LIB → SymbiYosys/Z3)
  • Closed complete k-induction proofs (BMC base case + inductive step at matched depth) over every sequential submodule, with proofs parametrised across representative MAX/WIDTH configurations as parallel sby tasks.
  • Diagnosed why enable-bearing designs defeat naive depth escalation: a spurious counterexample (e.g. count initialised above MAX) adapts to any depth by prepending enable-low cycles, so the fix is inductive-invariant strengthening, restoring the always @(*) count ≤ MAX bound, not a bigger k.
  • Worked through the valid-vs-reachable distinction underpinning induction soundness, including the block-type subtlety that always @(posedge clk) assertions check the previous cycle’s state (behaving as 0-induction), which is why the counter provably requires k = 2.
  • Applied the standard industrial division of labour: formal proof for local invariants at module level, cocotb simulation for sequence-dependent integration behaviour (start/lap/stop chains, mode transitions) where a formal spec would be as complex as the implementation itself.
Verification Infrastructure & Synthesis Insight
  • Maintained a zero-warning bar under Verilator --lint-only --Wall (width mismatches, implicit truncation/sign-extension) and Verible lint/format, with cocotb Python-coroutine testbenches orchestrated by pytest as a CI-style regression suite, estimated an order-of-magnitude cycle-time saving over a Quartus-only compile-and-probe loop.
  • Traced the Yosys synthesis pipeline stage-by-stage on real modules: elaboration ($lt/$add/$mux next-state logic), proc/opt (procedural blocks collapsed into an $sdffe with the declaration initialiser merged into the reset path), techmap (vector registers unrolled into per-bit $_SDFFE_PP0P_ primitives with explicit bit-slicing), and ABC gate mapping, including recognising when ABC passes a netlist through untouched because techmap’s output already sits inside the target gate library, and how the same netlist would instead map to LUT fabric on FPGA versus standard cells on ASIC.
